# 选型标准 — 笔记工具

## 一句话定义

从 swyx 和 Eric J. Ma 的公开文章中提炼的"选笔记/知识系统工具时应该看什么"。

## 综合标准表

从两人的文章交叉对照，可以归纳出以下维度：

| 标准 | swyx | Eric | 说明 |
| ---- | ---- | ---- | ---- |
| **Markdown** | ✅ 必须 | ✅ 必须 | 摩擦低、格式可迁移、Lindy、agent 友好 |
| **本地文件 / 数据自主权** | ✅ | ✅ 核心 | 不依赖云厂商；纯文本 = 你永远能读 |
| **双向链接** | ✅ 必须 | ✅ 图谱化 | 知识网络化，不是文件夹树 |
| **Git 化** | ✅ 必须 | — | swyx 强调 idea archaeology |
| **移动端** | ✅ 必须 | — | 随时捕捉（iCloud + GitJournal） |
| **发布能力** | ✅ 必须 | — | swyx 需要公开；Eric 用 Confluence 等外部渠道 |
| **AI / agent 可维护** | — | ✅ 核心 | Eric 的第一优先级：plain text = agent 能读写 |
| **AGENTS.md 规则** | — | ✅ | agent 需要明确契约才能稳定维护 vault |
| **多格式摄入** | — | ✅ | Word/PDF/PPT/Excel 都要能转进来 |
| **输出到多平台** | — | ✅ | Confluence/Jira/Gists/slides |

## 两人的分歧点

| 点 | swyx | Eric |
| -- | ---- | ---- |
| 公开性 | 必须公开 | 不强调（企业内部为主） |
| 付费意愿 | 明确愿付 $5-20/月 | 未提 |
| AI 深度 | 文中未提 agent 维护 | **核心**：agent 是 vault 的日常维护者 |
| 写作主体 | 人写 | **agent 写 + 人审** |

## 和 Karpathy 的对照

Karpathy 不讨论"选什么工具"，而是直接假设 Obsidian + LLM，更关心的是：

- raw / wiki / schema 分层
- 编译而非检索
- lint / health check

换言之：swyx 和 Eric 讲的是"**为什么选 Obsidian**"，Karpathy 讲的是"**选了以后怎么用 LLM 把它变成编译系统**"。

## 对你的启发

你已经选了 Obsidian，所以选型标准对你的价值不在于"再选一次"，而在于**验证你的配置是否齐全**：

- [x] Markdown + 本地文件 → vault 已建
- [x] 双向链接 → Obsidian 原生
- [x] Git → 刚刚 init
- [ ] 移动端 → 你有没有手机端 Obsidian？（需确认）
- [x] AI agent → Claude Code / Codex 已装
- [x] AGENTS.md → LLM-Wiki 已建
- [x] 多格式摄入 → markitdown + pandoc 刚装
- [ ] 发布 → 暂未配（不急）
