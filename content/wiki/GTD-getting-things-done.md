# GTD (Getting Things Done)

## 一句话定义

David Allen 2001 年提出的个人生产力方法论：通过将所有"stuff"外部化到受信系统，经过 Capture → Clarify → Organize → Reflect → Engage 五步，达到"Mind Like Water"的无压力高效状态。

## 五步流程

| 步骤 | 动作 | 关键问题 |
| ---- | ---- | -------- |
| **1. Capture** | 收集一切到收件箱 | "大脑里还有什么在转？" |
| **2. Clarify** | 逐条处理：可行动？ | "下一步物理行动是什么？" |
| **3. Organize** | 放入正确的列表/日历 | "属于哪个 bucket？" |
| **4. Reflect** | Weekly Review | "系统还可信吗？" |
| **5. Engage** | 按上下文/精力/时间选择行动 | "现在做什么最合适？" |

## 核心概念

- **"Stuff"** — 进入你世界的任何未明确下一步的事物
- **Mind Like Water** — 清空大脑后的平静聚焦状态
- **2 分钟规则** — 能在 2 分钟内完成的就立即做
- **Weekly Review** — GTD 的基石，定期回顾和维护系统
- **Next Actions** — 永远定义清楚"下一步具体行动"，而非模糊的待办
- **Someday/Maybe** — 暂不行动但不想丢弃的想法的安全收纳处

## GTD vs PARA：任务管理 vs 信息管理

| 维度 | GTD | [[PARA方法\|PARA]] |
| ---- | --- | ---- |
| 关注点 | **行动**——下一步做什么 | **信息**——放在哪里 |
| 核心单位 | Next Action / Project | Note / Folder |
| 提出者 | David Allen (2001) | Tiago Forte (2017) |
| 组织原则 | 按可行动性分流 | 按可行动性分层 |
| 回顾机制 | Weekly Review（内置） | 无内置回顾 |

两者高度互补：PARA 组织知识，GTD 驱动行动。Tiago Forte 明确说 PARA 的灵感来自 GTD。

## GTD vs CODE/BASB

| GTD 步骤 | [[building-a-second-brain\|BASB]] CODE 对应 |
| -------- | ---- |
| Capture | **C**apture — 几乎相同 |
| Clarify + Organize | **O**rganize — GTD 更精细（2分钟规则、委派、延后） |
| Reflect | 无直接对应（BASB 缺少系统性回顾） |
| Engage | **E**xpress — GTD 是执行任务，BASB 是产出创作 |
| — | **D**istill — GTD 没有提炼步骤 |

关键差异：GTD 优化**执行效率**，BASB 优化**知识复利**。

## 和知识管理的关系

GTD 不是知识管理方法——它是任务管理方法。但它的设计思想深刻影响了整个 PKM 领域：

| GTD 思想 | 知识管理中的体现 |
| -------- | ---- |
| "大脑是用来产生想法的，不是用来存放想法的" | [[building-a-second-brain\|BASB]] 的核心前提 |
| 外部化到受信系统 | 所有 PKM 方法的共同基础 |
| Weekly Review | [[LYT-linking-your-thinking\|LYT]] 的定期回顾实践 |
| Someday/Maybe | [[PARA方法\|PARA]] 的 Archive 概念 |
