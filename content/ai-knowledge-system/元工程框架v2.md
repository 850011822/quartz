## 五、任务调度系统

### 5.1 依赖关系图

```
TwitterScanner ─┬─→ SentimentAnalyzer ─┐
GitHubHunter ───┼─→ KnowledgeGraphBuilder─┼─→ StrategyGenerator ─┐
NewsAggregator ─┤                        └─→ OpportunityEvaluator ─┐
                │                                               │
                └───────────────────────────────────────────────┼─→ BacktestRunner ──→ AShareExecutor
                                                               │                        │
CryptoDataFeeder ──────────────────────────────────────────────┼─→ ArbitrageHunter ──→ CryptoExecutor
                                                               │                        │
StockDataFeeder ──────────────────────────────────────────────┴─→ RiskAssessor ────→ USStockExecutor
                                                               │                        │
MacroMonitor ─────────────────────────────────────────────────┘                        │
                                                                                        │
PerformanceAnalyzer ─────────────────────────────────────────────────────────────────┘
```

### 5.2 并行规则

```
✅ 可以并行：
- 所有情报组Agent（互相独立）
- 分析组的情感分析 + 知识图谱（同时进行）
- 回测 + 风险评估（同时进行）

❌ 必须串行：
- 策略生成 → 机会评估（顺序）
- 评估通过 → 执行（顺序）
- 错误发生 → 人工检查（暂停该分支）
```

### 5.3 优先级队列

```
P0 (最高)：实时报警、执行异常、市场剧变
P1 (高)：新机会发现、策略信号
P2 (中)：日常扫描、知识更新
P3 (低)：性能报告、长期分析
```

## 六、错误处理机制

### 6.1 错误分类

```
┌────────────────────────────────────────────────────────────┐
│ 错误类型                                                     │
├────────────────────────────────────────────────────────────┤
│ 🔴 致命错误：                                                │
│    - 账户登录失败                                           │
│    - API配额用完                                            │
│    - 资金不足                                               │
│    → 立即停止，通知人工                                     │
│                                                             │
│ 🟡 警告错误：                                                │
│    - 数据延迟                                               │
│    - 单次请求失败                                           │
│    - 回测超时                                               │
│    → 重试3次，失败则跳过                                    │
│                                                             │
│ 🟢 轻微错误：                                                │
│    - 某个数据源不可用                                       │
│    - 非核心指标缺失                                         │
│    → 降级处理，用备用数据源                                 │
└────────────────────────────────────────────────────────────┘
```

### 6.2 错误追踪日志

```json
{
  "timestamp": "2026-03-30 09:00:00",
  "agent": "CryptoExecutor",
  "error_type": "API_RATE_LIMIT",
  "message": "Binance API rate limit exceeded",
  "retry_count": 3,
  "action": "SWITCH_TO_BACKUP",
  "backup_source": "Coinbase",
  "resolved": true,
  "lesson": "需要接入多个交易所API分散请求"
}
```

### 6.3 故障恢复流程

```
Agent 停止
    │
    ▼
检查点保存 ← 最近一次成功状态
    │
    ▼
分析错误原因
    │
    ├─── 可恢复？ ────→ 重试 + 备用方案
    │                      │
    │                      ▼
    │                  成功？ → 继续
    │                      │
    │                      ▼
    │                  失败 → 人工通知
    │
    └─── 不可恢复？ ──── → 暂停 + 记录 + 人工介入
```

## 十七、守护者 Agent 详细职责

### 17.1 AgentWatchdog

`python
职责：
1. 每30秒检查所有Agent心跳
2. 记录Agent存活状态
3. 标记异常Agent
4. 触发恢复流程

检查点：
- Agent进程是否存在
- Agent最后响应时间
- Agent CPU/内存使用
`

### 17.2 ToolEvaluator

`python
职责：
1. 定期评估所有工具
2. 对比同类工具
3. 推荐最优工具
4. 标记需替换工具

评估标准：
- 可靠性 30%
- 成本 20%
- 效率 20%
- 覆盖度 15%
- 维护成本 15%
`

### 17.3 ToolDeduplicator

`python
职责：
1. 扫描所有工具定义
2. 识别功能重复
3. 分析使用情况
4. 建议合并或保留
5. 执行去重

判断重复的标准：
- 功能描述相似度 > 80%
- 数据源相同
- 目标相同
`

### 17.4 CostTracker

`python
职责：
1. 追踪所有成本
2. 生成成本报告
3. 超限报警
4. 优化建议

成本项：
- API调用次数和费用
- Token消耗
- 计算资源
- 人工介入时间
`

## 十八、自动故障恢复流程

`
故障发生
    │
    ▼
Step 1: 故障检测
- Watchdog发现心跳停止
- 记录故障时间、Agent ID
    │
    ▼
Step 2: 故障分类
- 崩溃？超时？内存不足？
- 查询历史故障模式
    │
    ▼
Step 3: 自动恢复
- 保存检查点
- 重启Agent
- 恢复状态
- 验证运行
    │
    ├─── 成功 ────→ 记录恢复日志 ──→ 继续运行
    │
    ├─── 失败 ────→ 进入隔离舱诊断
    │                      │
    │                      ├─── 可修复 ────→ 修复后重启
    │                      │
    │                      └─── 复杂故障 ────→ 通知人工 + 临时方案
    │
    ▼
Step 4: 经验归档
- 记录故障原因
- 更新检查点策略
- 预防建议
